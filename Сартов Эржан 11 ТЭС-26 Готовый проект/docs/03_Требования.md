# Требования

**Проект:** Система регистрации на экскурсии «MyГид». **Заказчик:** MyГид. **Автор:** [Сартов Эржан Бекжигитович, группа 11 ТЭС-26].
**Версия документа:** 1.0. **Дата:** 19.11.2026.

## Бизнес-требования

- **BR-1:** сократить время поиска и проверки бронирования туриста во время телефонного звонка.
- **BR-2:** обеспечить менеджерам «MyГид» единый интерфейс для контроля статусов заявок на экскурсии без ошибок в датах и количестве мест.
- **Показатель результата:** время поиска нужной записи снижается с 1–2 минут (поиск в бумажном журнале) до 10 секунд.

## Функциональные требования

- **FR-1:** система позволяет создать запись на экскурсию с автоматическим присвоением уникального номера и указанием названия экскурсии, даты, ФИО туриста, телефона и количества мест.
- **FR-2:** система отображает список всех записей в таблице и при выборе строки заполняет карточку справа для просмотра и редактирования.
- **FR-3:** система выполняет мгновенный поиск записей по номеру, ФИО туриста, телефону или названию экскурсии, а также фильтрует список по выбранному статусу.
- **FR-4:** система позволяет изменять статус записи строго по правилам: `Новая → Подтверждена → Завершена`, а также `Новая → Отменена` и `Подтверждена → Отменена`; остальные переходы запрещены.
- **FR-5:** система удаляет выбранную запись только после подтверждения действия пользователем в диалоговом окне.
- **FR-6:** система проверяет корректность ввода: все поля обязательны, дата соответствует формату `ДД.ММ.ГГГГ`, количество мест — целое число от 1 до 20.

## Нефункциональные требования и ограничения

- **NFR-1:** список из 10 записей открывается и фильтруется не более чем за 1 секунду на стандартном офисном ПК (CPU 2 ядра, 4 ГБ ОЗУ).
- **NFR-2:** при попытке сохранить пустые обязательные поля или неверный формат даты выводится понятное окно с описанием ошибки, некорректная запись не создаётся.
- **NFR-3:** приложение работает на ОС Windows 10/11, Linux и macOS с установленным Python 3.11+ и Tkinter; интерфейс читаем при разрешении от 900×560 пикселей.
- **Ограничения:** срок разработки 6 недель; один разработчик; стек Python + Tkinter без внешних зависимостей и СУБД; данные хранятся только в оперативной памяти до закрытия окна.
- **Приоритеты:** требования FR-1 — FR-6 и NFR-1 — NFR-3 являются обязательными для выпуска v1.0.
